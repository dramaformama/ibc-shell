# Как проверять iBC Shell

Две части: что запускает машина (минута-две) и что надо пройти руками (15 минут).

## 1. Автопроверки: «всё ли цело»

Запускать в корне проекта. Если все пять зелёные, код собирается и логика работает.

| Команда | Что проверяет | Что значит «зелёный» |
| --- | --- | --- |
| `cargo clippy --workspace --all-targets -- -D warnings` | Rust-код на ошибки и сомнительные места | нет предупреждений |
| `cargo test --workspace` | Хранилище, шифрование, SSH, SFTP (передачи, докачка, конфликты имён) | везде `ok`, `0 failed` |
| `cargo deny check` | Лицензии и известные уязвимости зависимостей | `ok` |
| `pnpm -C ui check` | Типы интерфейса | `0 ERRORS` |
| `pnpm -C ui test` | Логика интерфейса (поиск, вставка, автоблокировка) | все `passed` |

Первая сборка после чистки долгая (несколько минут), дальше быстро.
Большой тест SFTP (гигабайтный файл) по умолчанию берёт 96 МиБ, чтобы не ждать: `IBC_BIG_MIB=1024 cargo test -p ibc-shell-sftp` для полного.

**Против настоящего сервера:** `just e2e` поднимает в Docker тестовые серверы OpenSSH (нужен Docker или colima) и гоняет по ним клиент. Логин `tester`, пароль `test-pw-123`.

## 2. Руками: пройти приложение глазами

Запуск: `pnpm tauri dev`. Откроется окно приложения.

Для проверки нужен любой SSH-сервер. Проще всего тестовый из Docker: `docker compose -f tests/docker/compose.yml up -d`. Серверы слушают порты 2201-2205 на `localhost`, логин `tester`, пароль `test-pw-123`.

Пройдите по порядку и отмечайте, что не так:

1. **Первый запуск.** Хранилища нет → экран «создать мастер-пароль» с подтверждением. Создайте. Закройте и откройте: должен спросить пароль.
2. **Язык.** Настройки → язык. Переключите ru ↔ en, текст меняется сразу и сохраняется после перезапуска.
3. **Папки и флаги.** Создайте папку, вложенную папку, добавьте хост, выберите флаг страны. Хост виден в дереве.
4. **Подключение.** Откройте хост. При первом подключении приложение покажет отпечаток ключа сервера и спросит доверие. Примите. Появится терминал: наберите `ls`, `top`, нажмите `q`. Проверьте, что кириллица и цвета отображаются.
5. **Смена ключа сервера (важно для безопасности).** Пересоздайте тестовый сервер (`docker compose down && up -d`) и подключитесь снова. Подключение **должно быть заблокировано** с понятным предупреждением, а не пройти молча.
6. **SFTP.** Откройте SFTP для хоста: две панели. Загрузите файл, скачайте файл, переименуйте, удалите. Загрузите папку. Во время большой передачи нажмите паузу, потом продолжить.
7. **Конфликт имён.** Загрузите файл с уже существующим именем: появится выбор (заменить, пропустить, переименовать).
8. **Обрыв.** Во время передачи остановите контейнер (`docker stop`), потом запустите и возобновите. Файл должен докачаться, не начаться заново.
9. **Блокировка.** Настройки → автоблокировка 1 минута. Не трогайте приложение минуту: должно заблокироваться и снова попросить пароль. Открытые вкладки не должны показывать содержимое на экране блокировки.
10. **Вставка.** Вставьте в терминал многострочный текст: приложение должно предупредить, а не выполнить его сразу.

Что считать провалом: пустой экран, зависание дольше пары секунд, любое сообщение про «unwrap» или «panic», молча принятая смена ключа, пароль в любом виде на экране или в логе.

### Метрики сервера

1. Откройте терминал Linux-сервера. Кнопка «Состояние сервера» справа в полосе вкладок показывает инспектор CPU, нагрузки, RAM, сети, диска и восьми процессов. Данные обновляются, терминал принимает ввод и меняет размер при открытии/закрытии инспектора.
2. Нажмите «Сводка» (сетка рядом с кнопкой боковой панели): карточки открытых серверов показывают CPU/RAM, сеть, ядра, объём RAM и диска, аптайм. Счётчики отражают состояние открытых серверов. Нажатие карточки возвращает к серверу без повторного входа.
3. Переключайте «Сводка» → терминал → файлы: соединения терминала сохраняются, инспектор виден только в терминале. Закройте сервер: его карточка исчезает. Без открытых серверов показан приветственный экран.
4. Перезапустите приложение: выбранная видимость инспектора сохраняется. Проверьте светлую и тёмную темы, русский и английский языки.
5. На сервере без Linux инспектор/карточка показывают сообщение о неподдерживаемых метриках. Отсутствующие числовые данные отображаются как «—», графики имеют разрывы.
6. При скрытых сводке и инспекторе новых запросов `stats_sample` быть не должно (текущий запрос может завершиться). Опрос не должен сбрасывать автоблокировку.

## 3. Где смотреть, если что-то сломалось

- Окно запущено через `pnpm tauri dev`: ошибки Rust печатаются в терминал, где его запустили.
- Ошибки интерфейса: правый клик в окне → «Inspect» (в релизной сборке инструменты разработчика отключены намеренно).
- Любая ошибка в хранилище или шифровании: сохраните текст ошибки, секретов в нём быть не должно (это правило проекта).
