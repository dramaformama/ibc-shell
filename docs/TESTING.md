# Как проверять iBC Shell

Две части: что запускает машина (минута-две) и что надо пройти руками (15 минут).

## 1. Автопроверки: «всё ли цело»

Запускать в корне проекта. Если все пять зелёные, код собирается и логика работает.

| Команда | Что проверяет | Что значит «зелёный» |
| --- | --- | --- |
| `cargo clippy --workspace --all-targets -- -D warnings` | Rust-код на ошибки и сомнительные места | нет предупреждений |
| `cargo test --workspace` | Хранилище, шифрование, SSH, SFTP (передачи, докачка, конфликты имён) | везде `ok`, `0 failed` |
| `cargo deny check` | Лицензии и известные уязвимости зависимостей | `ok` |
| `pnpm -C ui check` | Типы интерфейса | `0 ERRORS` |
| `pnpm -C ui test` | Логика интерфейса (поиск, вставка, автоблокировка) | все `passed` |

Первая сборка после чистки долгая (несколько минут), дальше быстро.
Большой тест SFTP (гигабайтный файл) по умолчанию берёт 96 МиБ, чтобы не ждать: `IBC_BIG_MIB=1024 cargo test -p ibc-shell-sftp` для полного.

**Против настоящего сервера:** `just e2e` поднимает в Docker тестовые серверы OpenSSH (нужен Docker или colima) и гоняет по ним клиент. Логин `tester`, пароль `test-pw-123`.

## 2. Руками: пройти приложение глазами

Запуск: `pnpm tauri dev`. Откроется окно приложения.

Для проверки нужен любой SSH-сервер. Проще всего тестовый из Docker: `docker compose -f tests/docker/compose.yml up -d`. Серверы слушают порты 2201-2205 на `localhost`, логин `tester`, пароль `test-pw-123`.

Пройдите по порядку и отмечайте, что не так:

1. **Первый запуск.** Хранилища нет → экран «создать мастер-пароль» с подтверждением. Создайте. Закройте и откройте: должен спросить пароль.
2. **Язык.** Настройки → язык. Переключите ru ↔ en, текст меняется сразу и сохраняется после перезапуска.
3. **Папки и флаги.** Создайте папку, вложенную папку, добавьте хост, выберите флаг страны. Хост виден в дереве.
4. **Подключение.** Откройте хост. При первом подключении приложение покажет отпечаток ключа сервера и спросит доверие. Примите. Появится терминал: наберите `ls`, `top`, нажмите `q`. Проверьте, что кириллица и цвета отображаются.
5. **Смена ключа сервера (важно для безопасности).** Пересоздайте тестовый сервер (`docker compose down && up -d`) и подключитесь снова. Подключение **должно быть заблокировано** с понятным предупреждением, а не пройти молча.
6. **SFTP.** Откройте SFTP для хоста: две панели. Загрузите файл, скачайте файл, переименуйте, удалите. Загрузите папку. Во время большой передачи нажмите паузу, потом продолжить.

   - Выделите текстовый файл и нажмите пробел, затем повторите двойным щелчком и через меню «Просмотреть». Проверьте поиск, перенос строк, копирование и закрытие по Esc.
   - Для UTF-8 лога больше 5 МиБ проверьте переключение начала и конца, видимую пометку об усечении, «Показать больше» и обновление после дописывания строк. Повторите на сервере с доступом только по SFTP.
   - Для пустого файла и ссылки на текст проверьте содержимое. Для PDF и двоичного файла проверьте сообщение и действия открытия в системном приложении или скачивания.
7. **Конфликт имён.** Загрузите файл с уже существующим именем: появится выбор (заменить, пропустить, переименовать).
8. **Обрыв.** Во время передачи остановите контейнер (`docker stop`), потом запустите и возобновите. Файл должен докачаться, не начаться заново.
9. **Блокировка.** Настройки → автоблокировка 1 минута. Не трогайте приложение минуту: должно заблокироваться и снова попросить пароль. Открытые вкладки не должны показывать содержимое на экране блокировки.
10. **Вставка.** Вставьте в терминал многострочный текст: приложение должно предупредить, а не выполнить его сразу.

Что считать провалом: пустой экран, зависание дольше пары секунд, любое сообщение про «unwrap» или «panic», молча принятая смена ключа, пароль в любом виде на экране или в логе.

### Сводка и единый интерфейс (ADR-010)

1. После разблокировки главная показывает **все сохранённые серверы**, даже без вкладок. Пока нет наблюдения — «Не проверен», а не «Недоступен». Через несколько секунд видимые карточки получают доступность TCP-порта и время соединения. Это не проверка учётных данных или здоровья сервера. Для хоста через jump без SSH-сессии состояние остаётся неизвестным.
2. Счётчики «Всего / В сети / Не в сети / Не проверены» — фильтры. Поиск работает по имени, адресу и папке; пустой результат имеет отдельный экран. Прокрутите большой каталог: отрисовываются только видимые строки карточек с небольшим запасом. Непроверенные/просроченные наблюдения не засчитываются как offline.
3. Подключите Linux-сервер, вернитесь в «Сводку» через боковую панель: CPU/RAM, сеть и ресурсы появляются на карточке; другие сохранённые серверы остаются видны. Несколько подключений дают несколько живых карточек. Кнопки «Терминал», «Файлы», «Изменить» работают независимо. Ошибка входа отличается от недоступного порта.
4. «Состояние сервера» справа в toolbar показывает инспектор. Терминал принимает ввод, меняет размер при открытии/закрытии; видимость инспектора сохраняется после перезапуска. В узком окне он становится боковым наложением. На сервере без Linux — сообщение о неподдерживаемых метриках. Пропуски отображаются «—», ошибки обновления — «Данные устарели».
5. С подключённым терминалом откройте «Файлы»: SFTP использует его SSH-соединение, без повторного логина. Перейдите в папку, выделите файл, откройте сводку и вернитесь: каталог, выделение и соединение сохраняются. Закрытие сервера закрывает обе панели. Если терминала нет, SFTP может открыть самостоятельное соединение.
6. Настройки/редактор хоста/папки/диалоги/файлы используют одинаковые кнопки и поля: primary, secondary, ghost и компактный вариант; одинаковый фокус и disabled. Проверьте обе темы, ru/en, клавиатуру, уменьшение окна до 420 px и reduced motion. Переключатели настроек выглядят одинаково.
7. При скрытых сводке и инспекторе новых `stats_sample` быть не должно; `host_probe` вызывается только для наблюдаемых карточек (≤4 одновременно, повтор через 30 с). Текущие запросы могут завершиться. Опросы пассивны для автоблокировки; блокировка отменяет очередь проверок и очищает наблюдения. Проверить автоблокировку вживую.
8. Подключение по шагам. В демо-режиме (`pnpm -C ui dev`, быстрое подключение через ⌘K) введите `root@refused.example`, `root@timeout.example`, `root@dropped.example`, `root@badauth.example`, `root@dns.example`: у каждого своя карточка с шагами, временем и объяснением. `root@slow.example` показывает «ждём ответа · N с из 15». «Скопировать отчёт» кладёт в буфер текст без секретов. С настоящим сервером: неверный порт даёт «отказал в соединении», неверный пароль даёт список способов, которые принимает сервер.
9. Конфигурация сервера. На карточке «Сводки», в «Состоянии» и в строке сервера видны ядра, память, диск и тип, а на широких экранах и процессор. На виртуальной машине тип диска может быть не назван.
10. Резервная копия. Настройки → «Резервная копия»: сохранить с паролем (не меньше 10 символов, дважды), восстановить на чистой установке: серверы, ключи, сниппеты, настройки и тема на месте, страница перезагружается. Неверный пароль даёт «Неверный пароль».
11. Плотность списков. Настройки → «Плотность списков» → «Компактно»: строки серверов, дерево и процессы плотнее, вторая строка с конфигурацией у сервера скрыта.

### Версия 1.0.0: локальный терминал, вкладки, Файлы, уведомления (ADR-017)

1. **Локальный терминал.** В боковой панели строка «Локальный терминал». Откройте: ваша оболочка, домашняя папка, работают цвета, кириллица, `vim`, `top`. Наберите `exit`: оболочка сразу запускается заново. Перейдите на сервер и обратно по <kbd>⌃`</kbd>: история на месте. В панели вкладок локального терминала нет, <kbd>⌘W</kbd> его не закрывает.
2. **Порядок вкладок.** Откройте 3 сервера. Перетащите первую вкладку в конец: соседние плавно расступаются, после отпускания порядок новый, терминалы не переподключаются (вывод на месте). Короткий щелчок без движения просто выбирает вкладку. <kbd>⌥←</kbd>/<kbd>⌥→</kbd> на вкладке двигают её. <kbd>⌘1…9</kbd> следуют новому порядку.
3. **Терминал → Файлы.** На Ubuntu/Debian выполните `cd /etc`, правой кнопкой → «Открыть эту папку в „Файлах“»: справа открыт `/etc`. На сервере без заголовка `user@host: dir` пункт неактивен, пока оболочка не сообщит папку (OSC 7).
4. **Перетаскивание в терминал.** Перетащите файл из Finder на терминал сервера: рамка «Отпустите, чтобы загрузить в …», после отпускания плашка «Загружаю…», файл появился в папке (`ls`). Повторите: появится копия `имя (1)`, оригинал не тронут. На локальный терминал перетаскивание вставляет путь в кавычках, если в нём пробелы.
5. **Метки и уведомления.** В терминале сервера `sleep 20; echo ok`, перейдите на другую вкладку: через 20 с синяя точка на вкладке и плашка «…: Команда завершилась». Повторите и переключитесь в другую программу: системное уведомление (macOS спросит разрешение один раз). `tail -f` в фоне даёт точку, но не уведомление. Выключите в Настройках → Терминал: уведомлений нет. В демо-режиме есть команды `sleep N`, `bell`, `cd`, `pwd`.

### Оформление окна и открытие файлов (ADR-018)

1. На macOS проверьте положение системных кнопок при открытой и скрытой боковой панели. На Windows/Linux проверьте кнопки «Свернуть», «Развернуть», «Восстановить» и «Закрыть», в том числе до разблокировки.
2. Перетащите окно за свободное место верхней панели, дважды щёлкните там же, потяните за края. Проверьте узкое окно, обе темы, поиск и перетаскивание вкладок.
3. Дважды щёлкните по удалённому `example.txt`, затем повторите через Enter и контекстное меню. В диалоге нажмите «Открыть»: системное приложение показывает временную копию, очередь передач пуста. «Скачать» сохраняет файл в каталог локальной панели, в том числе в домашнюю папку.
4. Откройте локальный документ, пустой удалённый файл и ссылку на документ. Двойной щелчок по каталогу или ссылке на каталог выполняет переход. Для исполняемого или слишком большого удалённого файла появится сообщение, в диалоге останется доступно скачивание.

### Отдельные окна хостов (ADR-019)

1. В установленной сборке откройте два сохранённых хоста через ПКМ в сайдбаре → «Открыть в новом окне». У каждого окна загружается содержимое и работает переключатель «Состояние / Терминал / Файлы».
2. Откройте вкладку SFTP и выберите тот же пункт в её контекстном меню. Новое окно откроется на «Файлах» в тех же каталогах, вкладка исчезнет из главного окна. До переноса задайте переменную в терминале, запустите длительную команду и откройте сниппеты. После переноса проверьте переменную, вывод команды, историю терминала и доступность сниппетов, состояния и обзора. Закройте новое окно и проверьте, что другие окна работают.
3. Перетащите вкладку внутри полосы для смены порядка. Перетащите её вниз за полосу и отпустите: появится отдельное окно. Повторите для единственной вкладки. Escape или отмена указателя не должны открывать окно.
4. Запустите передачу в двух окнах. Открытие и закрытие одного окна не отключает события передач в другом.

## 3. Где смотреть, если что-то сломалось

- Окно запущено через `pnpm tauri dev`: ошибки Rust печатаются в терминал, где его запустили.
- Ошибки интерфейса: правый клик в окне → «Inspect» (в релизной сборке инструменты разработчика отключены намеренно).
- Любая ошибка в хранилище или шифровании: сохраните текст ошибки, секретов в нём быть не должно (это правило проекта).
